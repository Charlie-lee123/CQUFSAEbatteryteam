# CQUFSAE 串口助手 v2.10

> Windows 10 / 11（64 位）
> 自 v2.9 以来的所有改进一并汇总在本版。

## 本次重点：启动更快、代码更干净

### 启动链路实测与代码清理
对启动链路做了逐段计时：**历史库、车辆档案、DLC 都不在关键路径**（分别 4ms / 0.4ms / 就绪后才加载），
真正的一次性开销是 Qt 字体引擎初始化。曾尝试把这笔钱挪到开屏首帧之后，A/B 实测虽然首帧略早，
但**总就绪时间从 2.2 秒恶化到 3.9 秒**（预热不再与模块 import 重叠），已回滚并保留原方案。
这轮没有以牺牲总启动时间为代价换取"看起来更快"。

### 代码清理
- 删除一批从未被读取的函数参数与冗余缓存字段（`main_window` / `soc_feed` / `ui_settings` / `ui_surface`），行为零变化。
- 合并冗余的显示缓冲：合并期只保留真正要上屏的文本。

## 新增

### SOC 数据来源可选
底栏 SOC 区可以选择显示**本地估算**或**车端 BMS 上报**的 `SOC=`。设置面板 →
「SOC 数据来源」。切换来源不重建估算器、不打断数据链路，切回来读数连续。

### 显示行数按每个模组算
「电压数据行数 / 温度采集数据行数」的语义是**每个模组各显示成 N 行**，并且**视口优先**：
任何一排都不超出视口宽度，避免软换行把一行劈成参差不齐的短行。行数跟着车号档案走。

### 历史数据采样间隔
10~300 秒、10 秒一档，共 30 档。弹层最多显示 8 行并带滚动条，不会撑出屏幕；
行数始终是整行，不会出现被切掉一半的条目。

### 近期 / 历史数据分层
- 近期数据：`近期数据\{车号}.log`，保存屏上排版后的文本，用于看瞬时报错；
- 历史数据：`历史数据\{车号}.db`，append-only SQLite，永不删除，用于按间隔回看长期变化。
老的单库会自动迁移到新结构，数据不丢。

### 历史回放按需加载
打开历史回放只载入一页，向上滚动时再往前取，超大历史文件的打开不再卡住。

## 修复

- **串口分包导致的行数错乱**：一个模组被切成两块时，按档案点数而不是块内点数排版，
  屏上不再出现 `2+2+2+2` 这种半截行；复制出来的文本也按同一规则对齐小数点。
- **半截采样点拼接**：`9.` + `3890` 被分包切断时自动拼回一个点，点数守恒。
- **序号着色包含小数点**，颜色不再只盖住序号数字。
- **历史回放行数同步**：历史文件里存的是排版固化文本，回放前摊平成「一模组一行」再按当前行数重排。
- **历史翻页重复桶**：同一个 10 秒采样桶不再被反复吐出，采样间隔设置真正生效。
- **车端 SOC 单独成块**：`SOC=80.40%` 被串口缓冲切成单独一块时，「车端 BMS」模式立即刷新，不再慢一轮。
- **开屏动画卡顿**：字体/图标/控件的冷启动开销挪到开屏静止段，落点段不再被阻塞。
- **车号切换叠影**：过渡层的重复合成问题已结案，切换时只有一套内容。
- 设置面板外观区三只下拉框同宽对齐；材质强度滑杆与它们共用右缘。

## 其他改进

- 降低接收数据时的界面能耗：整卡闪烁从每收一块触发改为限频，最小化时完全停止。
- 串口端口轮询从 1 秒放宽到 4 秒。
- 安装包与单文件体积在 v2.9 基础上继续保持精简。

## 已知限制

- 单文件版（`SerialAssistant.exe`）每次启动都要把内置资源解压到临时目录，这一步在 Python 启动之前，
  本版未改动分发架构；安装版与单文件版行为一致。
- 「最大化时保留任务栏」下，窗口客户区比 Windows 工作区每边约多 7 逻辑像素，会压住任务栏顶沿一条细线。
