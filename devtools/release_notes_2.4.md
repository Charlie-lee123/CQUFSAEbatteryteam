## v2.4 —— 断线标记、排版不再改动设备数据、包体 −18%

### 新增：断线标记（相邻电芯压差）
- 设置 → 定制功能 → **断线阈值**（mV，0 = 关闭）。某个电芯比上一个电芯**低/高出一个阈值**时，就在它那一侧插一个洋红加粗的 `X`：
  **偏低只标在右边、偏高只标在左边**，一根断线只出一个 `X`。
- 一号电芯没有"上一个"，用**本模组正常电芯的平均值**判定（坏的那个不参与平均）。
- `X` 占用原有的列间隔，**行宽一格不变、列起点不漂**；跨行处的标记落在上一行行尾。

### 修正：接收区不再篡改设备发来的数据
- 以前会把连续几条数据行**合并重排**（设备发 `4+4` 两行温度，会显示成一行 8 个）。
  现在**一条设备行 = 一行显示**，只做补零与等宽对齐；行宽超视口时才拆这一行。
- 空行规则固定：每个 `VoltageN:` / `TemperatureN:` / `BMS …` 之上各空一行，其余位置没有。

### 修正：BMS 与历史回放
- **BMS Error 只标那几个字**（不再把后面的错误明细整行铺色），并且**不再区分大小写** ——
  真机发的是 `BMS Error`，旧版写死全大写 `BMS ERROR`，所以从来没标过色。`BMS OK` 一个字都不标。
- **历史回放与实时逐行一致**（空行、补零、着色都对得上），打开即**停在最新一轮**；
  老记录打开也会按同一规则重建空行。

### 修复：设置里的「检查更新」点了没反应
- 真因：版本源现在是 **4 元组**（多带一个镜像前缀），面板里仍按 3 元组解包 →
  点下去立刻抛 `ValueError`；Qt 把槽里的异常吞进 stderr，而 exe 没有控制台，
  所以屏幕上一个字都不变。
- 现在按钮会正常走完：`检查中…` → `✓ 已是最新`（或 `发现 vX.Y！`），版本行同步更新；
  新增自测用例用假网络把这条反馈链路钉住（不联网也能跑）。

### 其他修复
- 设置面板右侧的「温度采集数量」输入框不再被面板边界裁掉（面板按内容撑宽）。
- 自测从 28 项增加到 28 项（新增段状态/阈值、断线标记、空行规则、回放一致性等断言）。

### 体积
- **34.4 MB → 28.1 MB（−18%）**：去掉 Qt 的多语翻译库（本程序自己画界面，从不加载翻译）与
  **Qt 的 OpenSSL 后端**（Windows 上 Qt 默认用系统 Schannel）。
- 新增 `SerialAssistant.exe --check-net` 命令行探针：用**产品同一条网络栈**取一次 HTTPS 并把结果写进
  `net_check.txt` —— 这是"去掉 OpenSSL 后端"唯一的联网风险点，每次发布都在产物上实跑一遍。


### 全量缺陷排查后修复（10 条，含 4 条必然触发）
- **安装版自动更新 100% 失败**：`UpdateDialog` 拿**本地**旧常量 `LATEST_SETUP_SHA256`
  去校验**下一版**的安装包 —— 跨版本必然不符，整条下载源试完报"所有下载源都失败了"。
  改成按资产取**远端** version.py 里这一版的哈希（`update_asset_and_hash`）。
- **哈希缺失时更新卡死**：说明文案与实现相反（注释写"退回大小/跳过校验"，代码直接判失败）。
  现在明确提示"服务端没有提供本版校验值（可能正在发布），请稍后再试"。
- **断网时"检查更新"能卡几分钟**：代理兜底多跑了整整一轮（层数判断差一），且每层都跑
  两轮全源（10 源 × 4s × 2 × 3 层）。现在第一层跑两轮、后两层各一轮，最多 3 轮。
- **只是打开设置点「确定」就会改掉配置**：滑杆会被显示器刷新率夹进量程（存 240、屏 60Hz
  → 显示 60），旧逻辑拿夹后的值跟存值比 → 判成"用户改过"→ 240 被永久写成 60 并打上
  chosen 标记。现在以"面板打开时的显示值"为基准，没拖动就不写回。
- **注册表脏值导致启动即退**：`rx_blocks` 被写成非数字时 `int()` 在启动路径抛异常，
  exe 无控制台 → 用户看到"双击没反应"。已加兜底 + 日志。
- 回放条/交叉淡入每次切换都新建补间且不回收（点几十次攒几十个僵尸对象）；
  历史目录不可写时 `_pending` 无上限增长；可编辑下拉的墨迹测量缺空图保护（横向折叠会崩）；
  `Tween.destroyed` 把控件对象当 `finished=True` 用（已显式化）；BLE 停止在界面线程
  等待 2 秒（改成一个轮询周期，调用方用 `finished` 兜底）。
- 另修两条**测试自身**的缺陷：暂停定位用例误把"恢复"当"暂停"测、默认值断言依赖用户
  当前配置（用户改过就假挂）；并修掉一个会让自测直接 fail-fast 崩溃的线程生命周期问题。

### 再瘦身：29.5 MB → 28.8 MB（累计 34.5 MB → 28.8 MB，−16.5%）
- 删 `tarfile` + `lzma/_lzma` + `bz2/_bz2`（唯一引用是 `shutil.unpack_archive`，从没用过）、
  `unicodedata`（唯一链路 `pathlib → urllib.parse → unicodedata`，且只在解析非 ASCII
  主机名时触发）、网络状态查询插件 `qnetworklistmanager.dll`（`QNetworkInformation` 没调用过）。
- 说明：`decimal`、CPython 的 `libcrypto/libssl`、三份 `MSVCP140` 都**查过依赖链/哈希**，
  删不得（前者被 `random` 真实需要；后两者是 BLE 与 SHA256 校验的基础）。
- 剩下的体积几乎全是 PySide6 本体（67 MB 载荷里 50.9 MB 是 Qt 的 DLL），再压只能上 UPX，
  会给杀软误报，不做。

### 更新提速：不开代理也快（2026-10-25）
- **检查更新改成"全源并行 + 取最新"**：10 个源同时发，先到者参与、**300ms 收敛窗口内取版本号最高**的那条
  （jsDelivr 边沿缓存滞后时，靠它让镜像的正确答案盖过旧答案）。实测**直连 1.05~1.59 秒**出结果；
  改前是"逐源串行 × 每源 4s × 2 轮 × 3 层代理"，最坏 4 分钟。
- **死代理不再白等**：开跑前 TCP 探一下系统代理端口（≤350ms），端口死了就直接从"直连"层开始
  （本机常见：Clash 关了、系统代理设置还指着 127.0.0.1:7897）。
- **下载改成多源并行抢跑**：一次起 2 条源，谁先下完且校验通过谁算数，另一条立即中断。
  离线探针（本地假镜像，慢源 8KB/60ms、快源整块）实测 **0.05s vs 串行 2.25s（41×）**，载荷逐字节一致。
- 设置面板的「检查更新」与启动自动检查**合并成同一份实现**（此前一个并行、一个串行）。
- `--check-net` 改为**逐源诊断**：一条命令列出 10 个版本源各自通不通（本例 6/10 可用），
  而不是只测一条 URL 就下"联网坏了"的结论。
