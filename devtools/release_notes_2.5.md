## 2. 新增：结构化导出（CSV 宽表 / JSON 嵌套）

位置：**设置 → 日志 → 「数据 CSV」/「数据 JSON」**

以前只能导出 `.log`（给人看的）。现在把**已接收的电压/温度**直接导成机器可用的表：

**CSV（宽表）** —— 一行 = 某一轮里的某个模组，电芯/温度各自展开成列：

| 时间 | 轮次 | 模组 | 电芯1(mV) | 电芯2(mV) | … | 温度1(℃) | … |
|---|---|---|---|---|---|---|---|
| 00:12:03.412 | 1 | 1 | 3871 | 3870 | … | 22.5 | … |
| 00:12:03.412 | 1 | 2 | 3868 | 3869 | … | 22.7 | … |

- 电芯统一按 **mV 整数**落盘（BMS 口径就是 mV，避免 `3.5999999` 这种脏值），温度保留一位小数
- 同一轮的各模组共用**同一个时间戳**，直接可画放电曲线
- Excel 里筛"模组=3"、或 pandas 里 `df.filter(like="电芯").min(axis=1)` 就是最弱电芯

**JSON（嵌套）** —— `rounds[] → modules[] → cells/temps`，带单位与导出元信息，适合脚本消费。

**采集口径**（重要）：数据在**收包当下**从原始帧解析，不依赖接收区显示的文本 ——
显示层有补零、网格重排、断线标记 X，反解析一定会错位。因此：
- 暂停、清空显示、翻历史都**不影响**已采集的数据
- 设备**分包**发送（每帧都带 `Voltage1:`）时按**同一轮**合并，不会切碎
- 设置里的模组/电芯数**与设备对不上**时，保留"最后一个不完整模组"而不是整轮丢弃
  （否则你会导出到空文件却不知道原因）
- 只保留最近 **500 轮**（约 2 MB），长时间跑不会吃内存

## 3. 新增：MCP「手动填写参数」面板

位置：**设置 → MCP Service → 「手动填写参数」**

客户端的「连接至自定义 MCP」是**逐项填**的（名称 / 类型 / 命令 / 参数 / 环境变量），
以前软件只给"一整段丢给 Agent"的接入包，手填的人还得自己从文字里抠路径。现在：

| 项 | 值（本机实测） |
|---|---|
| 名称 | `serial-assistant` |
| 类型 | `stdio` |
| 命令 | `C:\Users\<你>\.serialassistant\mcp\venv\Scripts\python.exe` |
| 参数 | `C:\Users\<你>\.serialassistant\mcp\serial_assistant_mcp.py` |
| 环境变量 | （留空） |

- 每项**单独一个复制按钮**，长路径中间省略、完整值在 tooltip 里
- 「重新导出服务文件」把 MCP 服务源码重写到「参数」那个路径（升级后代码会变）
- 保留「复制接入配置」：仍然可以整段丢给 Agent 让它自动装
- 没建过 venv 时，「命令」会退回普通 python 并在面板上提示先 `pip install mcp pyserial`
- 表里的单行文本框与设置面板其它输入框**同一套外观**（`surface_2` 底 + 描边 + 16px 圆角），
  只读态用更深一档的底表示"可复制但不可编辑"
- ⛔ 顺带加了一条自测守卫：全局 QSS 里**任何一个 token 拼错**都会让它之后的样式整段
  静默失效（按钮丢透明底、图标多出红点），现在 `stylesheet()` 生成完会断言"无残留
  `@token@` 且首尾规则都在"
