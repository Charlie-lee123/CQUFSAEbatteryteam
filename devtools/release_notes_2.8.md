# CQUFSAE 串口助手 v2.8

> Windows 10 / 11（64 位）· 免安装单文件 **33 MB**（原 47.3 MB）· 安装包 **35.7 MB**（原 48.6 MB）
> 本版本已并入原 v2.7 的全部改动 —— **对外只有 v2.8 一个版本**，v2.7 不再单独发布。

## 本次：软件瘦身

- **单文件 49.5 MB → 33.0 MB（−16.5 MB / −33%）**，安装包 50.9 MB → 35.7 MB。
- 最大一块来自 **numpy**：它只为「开屏高斯模糊」一个用途服务，却连带 19.6 MB 的
  OpenBLAS 数学库。现在 numpy 变成**可选**——没有它时开屏改用纯 Qt 的降采样近似，
  模糊尺度与真高斯同量级，只有淡入那 0.3 秒的纹理质感略平（其余每一帧逐位一致）。
- 顺手修掉一个隐藏缺陷：原先 numpy 一旦加载失败，`splash_motion` 会连同**整个开屏动画
  一起放弃**（裸 import 抛异常被外层兜住，表现为「没有开屏」）。现在降级后照常播放。
- 内置开屏的 4 个 mp4 与 4 张 poster 本就是「文件名占位」（内置方案走纯几何绘制，
  从不解码它们），换成等名占位文件，再省 4.3 MB + 1.6 MB。
- 删除约 100 行死代码：`_WINDOW_MORPH` 旧方案整块（被现行覆盖层方案取代后一直闸死）、
  `_arm_clock`、恒为 False 的 `_clock_ready`、5 处零读取的 `_fs_target`、
  `_set_soc_text` 兼容垫片、只写不读的 `_dec_want` / `_motion_hold_ms` /
  `RoundData.pack_v_raw`、未被调用的 `soc_profiles.supported()`、
  `PluginInfo.summary/homepage`。合并了两处重复块（滚动补间、高亮选区构造）。

## 重点：第一次装好就能直接读数据

这一版把「插上设备却读不了数」这一类问题，从**猜**变成**看得见**。

### 新增：随程序自带 USB 转串口驱动，一键安装（离线可用）

- 安装包/免安装版都自带 5 家驱动：**STLink 虚拟串口、CH340/CH341、CP2102/CP2104、
  FT232/FT2232、PL2303**（共 2.4 MB，全部为厂商签名包，含 WHQL）。
- **只在真的缺驱动时才开口**：插着设备且驱动库没有对应驱动，才会问一次；没插设备
  的机器一声不响。判断依据是「插着 + 我们带了 + 驱动库里没有」，不是「库里缺哪家」。
- 装驱动会弹一次管理员授权，约十秒。**赛场没有网络也能装**。
- 选过「以后再说」不会反复烦你：记的是「驱动包版本 + 你拒过哪几家」，只有后来插了
  **没拒过的新芯片**才会再问。

### 新增：打开成功却收不到数据时，直接告诉你卡在哪

串口「打开成功」只代表句柄拿到了。波特率不对、TX/RX 接反、设备没上电，表现完全
一样：状态栏写着"已打开"、接收区一片空白。现在 **8 秒没有收到任何字节**，状态栏会写

> `COMx 已打开，但没有收到数据 —— 检查波特率与接线`

并给一条限时提示（指名波特率、接线、是否上电）。收到第一个字节就自动消失。

### 修复：驱动安装的三个判定缺陷

1. **`pnputil` 退出码不再被当作成败**。实测 CH340 已在驱动库里再装一次，`pnputil`
   返回退出码 5，输出却是「已成功添加驱动程序包。(系统中已存在)」—— 旧代码把这判成
   安装失败。现在先看输出里的失败字样，再看成功/已存在字样，最后才退回退出码。
2. **不再「装了个空气还报成功」**。旧代码只在某个 inf 失败时累加失败数，一个 inf 都
   没找到时同样是 0 失败，于是父进程报告"装好了"，驱动库里却什么都没有。现在统计
   实际尝试数，为 0 直接报失败并写明原因。
3. **等授权不再干等 3 分钟**。超时从 180 秒收到 120 秒，超时后明确说
   「等授权超时（2 分钟），驱动没有安装，可以再点一次」。

## SOC 估算（E74）

- 底栏正中直接给 **`SOC min` / `SOC max`** 与总电压（放电突出 min、充电突出 max；
  min/max 只取**真实读值**，绝不掺回填值），母线全断时标出「母线断开」。
- 算法 = **安时积分（骨架）+ κ 加权 OCV 回拉 + 静置软锚定（唯一强校正，增益 0.3、
  封顶 ±15%）+ 电流零漂在线学习**。
- **不上完整 EKF**：采样抖动 0.9~2.5 s 加上电流零漂会让协方差发散。设置里另有可选的
  四状态二阶 RC-PNGV EKF（`[SOC, U1, U2, Uc]`，默认关，发散自动回退 OCV 查表）。
- OCV 表从 26 点换成 **62 点**逐点标定（1C 放电曲线 + 82 mV 内阻修正），
  端点 100% ↔ 4.4981 V、0% ↔ 3.0818 V。参数按车号取（E74：125S、12.041 Ah、R0 6.8 mΩ），
  新车型只需加一条档案。
- **数据清洗**严格区分「断线回填」与「整模组不均衡保真值」：超量程必然回填，避免把
  接线故障伪装成没电。
- **电流判序修正**：「母线全断 + BMS 正常 ⇒ 真实电流必为 0」是硬件级事实，必须排在
  「读数越界」判断之前 —— 否则传感器没接时被换算成 −250 A 轨值，静置锚定整段会话里
  一次都不跑，SOC 只剩电压回拉。
- 底栏 SOC 四枚标签（SOC / 最低 / 最高 / 总压）夹紧排布，窄屏不越界。
- **实测**：闭环回放最大偏差 1.38%，静置与 OCV 查表一致 0.09%，零漂收敛约 1.41 A，
  SOC 始终落在 0~100。

## DLC（心率广播）

- 原先的「DLC 管理」按钮与动态插件入口收敛为**单颗「心率 DLC」开关**：
  开 = 启动插件并打开面板，关 = 停止。旁边保留一个低调的「卸载」入口。
- 插件放 `%LOCALAPPDATA%` 或 exe 同级 `dlc/` 即被挂载：校验 `api` / `min_app` / SHA256、
  防 Zip Slip、后缀白名单与体积上限，宿主全程异常隔离且不碰用户配置。
- 小米手环 8 代及以后：`0x180D` 广播 → GATT 订阅 `0x2A37`。
- 多设备：单 QThread + 单 asyncio 事件循环，每台一个 Task。

  需带库仑计满充 → 满放标定方可进一步收敛。
